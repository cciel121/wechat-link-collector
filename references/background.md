# 背景与能力边界

> 这是 `SKILL.md` 的深度补充材料。SKILL.md 里只留了结论性的警告，
> 完整的来龙去脉、观测记录都在这里。排查「为什么拿不到全量」时读本文件。

## 1. 为什么这事变难了：接口关闭时间线

微信已经关闭了「枚举某个公众号全部文章」的接口，**没有任何免登录方案能列出全量文章**：

| 时间 | 事件 |
|------|------|
| 2026-07-30 | 网页端历史文章列表接口 `appmsgpublish` 关闭 |
| 约 2026-09-16 | 客户端 `profile_ext?action=getmsg` 被拦截（PC 微信 4.x 转向 `channels.weixin.qq.com`） |
| PC 微信 3.9.x 现状 | **老「历史消息」窗口已下线**，改由「公众号主页窗口」承担（路径 A++） |

连带后果：wechat-article-exporter / `down.mptext.top`、qiye45/wechatDownload、
各类付费 API 在同期陆续失效。

**不讲清楚这一段就开始动手，用户会以为能一键抓完，然后一起浪费半天。**

## 2. 本技能的真实能力（三项，均已完整验证）

1. 读出**公众号主页窗口里的文章索引**（日期 / 标题 / 阅读数）—— 已完整验证；
2. 用 UIA 让微信把每篇开进**系统默认浏览器**，从浏览器窗口读**永久短链**（`/s/xxx`）
   —— 已完整验证，**实测某公众号 103 篇全量 103/103 成功**（路径 A+++）；
3. 若列表接口还活着，重放它一次拿全 —— 要先验证，见 `alternate-paths.md` 的路径 C。

## 3. 最容易被误判的一点：能读到多少，取决于页面加载了多少

- 同一个窗口、同一个脚本，实测读到过 **20 篇**，也读到过 **103 篇**
  （后者覆盖该号 2020→2026 的**全部**文章）。
- 差别**不在脚本**，在**页面有没有把列表加载完**。我方的程序化滚动始终没打通
  （原因见 `uia-internals.md` 第 14 条），
  但**用户手动把列表滚到底之后，整个列表在 UIA 里都是可读的**。
- 所以正确做法是：**先请用户在公众号主页窗口里手动滚到底，再跑脚本。**
- **不要跑一次就告诉用户「这个号只有 20 篇」** —— 我犯过这个错，并因此写错过文档。
- 无论拿到多少，脚本都按 URL 归一化去重并**自动合并进已有文件**，可以分多次累加。

> 这条是本技能最贵的一课：它把一个「能力上限」的假结论，纠回成「页面加载状态」的可解决项。
> 判断「能不能拿全」最稳的办法不是推理，而是**请用户滚到底，再跑 `--list` 看条数**。
